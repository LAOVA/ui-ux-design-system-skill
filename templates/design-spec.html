Direction Principles

  • Hierarchy First: Use typography, spacing, and contrast before decoration.
  • Semantic Restraint: Color and motion should reinforce meaning rather than create noise.
  • System Reuse: Reapply the same logic across marketing, app, and support surfaces.

Drift Risks

Common failure modes include overusing accent color, inventing page-specific spacing values, or switching visual tone between surfaces. Keep the system stable and let layout/content carry variation.

Layout Rhythm

The pattern should remain consistent enough that new pages inherit a recognizable rhythm. Section order, CTA placement, and content grouping should all feel deliberate and repeatable across product surfaces.

Density Guidance

Adjust density through spacing and grouping, not by inventing new component styles. Dense interfaces should still preserve scan paths and clear action hierarchy.

Token Naming Rules

  • Semantic First: Prefer names like primary, muted, and border over visual names.
  • No Page-Specific Tokens: Avoid creating one-off tokens for individual screens or campaigns.
  • Use Scales: Spacing, radius, and elevation should come from shared steps rather than ad hoc values.

Token Adoption

Implementation should reference token names in code, documentation, and review comments. If a team needs a new token, it should be added to the system intentionally rather than inline in component code.
