Performance and Accessibility

  • Performance: ⚡ Good
  • Accessibility: ◐ Ensure WCAG
  • Effects: Large sections (48px+ gaps), animated patterns, bold hover (color shift), scroll-snap, large type (32px+), 200-300ms

Direction Principles

  • Hierarchy First: Use typography, spacing, and contrast before decoration.
  • Semantic Restraint: Color and motion should reinforce meaning rather than create noise.
  • System Reuse: Reapply the same logic across marketing, app, and support surfaces.

Drift Risks

Common failure modes include overusing accent color, inventing page-specific spacing values, or switching visual tone between surfaces. Keep the system stable and let layout/content carry variation.

Layout Rhythm

The pattern should remain consistent enough that new pages inherit a recognizable rhythm. Section order, CTA placement, and content grouping should all feel deliberate and repeatable across product surfaces.

Density Guidance

Adjust density through spacing and grouping, not by inventing new component styles. Dense interfaces should still preserve scan paths and clear action hierarchy.

Typography Notes

  • Mood: A luxury-automotive brand whose marketing surfaces read as cinematic editorial. The base canvas is **near-black** (`#181818`) holding pure white display type; white-canvas bands appear only inside specific editorial contexts (preowned listings, pricing tables). The single brand voltage is **Rosso Corsa** (`#da291c`) — the iconic Ferrari racing red — used scarcely on primary CTAs, the Cavallino mark, and Formula 1 race-position highlights. Type runs **FerrariSans** at modest weights (display 500, body 400) — never bombastic. Spacing follows an explicit 8px token ladder (`xxxs` 4px through `super` 128px); generous editorial pacing throughout. The brand's strongest visual signature is the **full-bleed cinematic hero photograph** that fills the viewport top with car photography, model details, or trackside livery — followed by a tighter editorial body layout below.
  • Best For: Creative tools, Gen-Z marketing, e-commerce for youth culture, content portfolios, collage-style apps
  • Google Fonts: Open reference

Token Naming Rules

  • Semantic First: Prefer names like primary, muted, and border over visual names.
  • No Page-Specific Tokens: Avoid creating one-off tokens for individual screens or campaigns.
  • Use Scales: Spacing, radius, and elevation should come from shared steps rather than ad hoc values.

Token Adoption

Implementation should reference token names in code, documentation, and review comments. If a team needs a new token, it should be added to the system intentionally rather than inline in component code.

Rules and Risks

Keep these close during implementation and review so quality does not drift late in delivery.

Accessibility

  • Contrast ratio 4.5:1 or better for body text.
  • Visible focus states on all interactive elements.
  • Minimum touch target around 44 by 44 pixels.

Responsive

  • Use mobile-first layouts and avoid horizontal scrolling.
  • Adapt density and gutters at tablet and desktop widths.
  • Preserve readable line length and safe tap spacing.

Avoid

  • Flat design without depth
  • Text-heavy pages

Implementation

Use this checklist to move from system definition into code without losing consistency across components and pages.

Build Checklist

  • Map all UI surfaces to semantic tokens before implementation begins.
  • Keep component variants constrained and name them before coding one-off exceptions.
  • Review contrast, focus visibility, and spacing density before shipping.
  • Validate responsive collapse order on mobile, tablet, and desktop breakpoints.

Handoff Notes

Design, engineering, and review should all reference the same tokens, component rules, and accessibility constraints. Treat this document as the baseline system contract and keep page overrides separate and explicit.
